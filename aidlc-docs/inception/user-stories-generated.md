## 用户故事 1: 版本测试记录管理

### 故事卡片
**ID**: US-001
**优先级**: P0 (必须)
**复杂度**: 中等
**工作量**: 3-4 小时

### 故事描述
**作为** 测试工程师
**我想** 能够添加、查看、编辑和删除版本测试记录
**以便** 追踪每个版本的测试进度和结果

### 验收标准
- [ ] AC1: 能够在表单中输入版本号、修改内容、修改模块、风险等级等信息
- [ ] AC2: 能够点击"添加"按钮保存新的版本测试记录到本地数据库
- [ ] AC3: 能够在表格中查看所有版本测试记录，显示所有关键字段
- [ ] AC4: 能够点击记录进行编辑，修改后保存更新
- [ ] AC5: 能够选择记录并删除，删除前显示确认对话框
- [ ] AC6: 能够按版本号、修改模块、风险等级进行搜索和筛选
- [ ] AC7: 表格支持排序（按版本号、日期等）
- [ ] AC8: 页面刷新后数据仍然存在

### 业务规则
- 版本号必须唯一
- 风险等级只能是：低/中/高
- 修改模块可以多选
- 测试结果只能是：通过/失败/待定

### 技术考虑
- 使用 IndexedDB 存储数据
- 实现分页加载（每页 20 条）
- 支持本地搜索和筛选
- 使用 React 组件实现表格

## 用户故事 2: AI 用例推荐

### 故事卡片
**ID**: US-002
**优先级**: P1 (重要)
**复杂度**: 高
**工作量**: 4-5 小时

### 故事描述
**作为** 测试工程师
**我想** 输入版本信息后，AI 能够推荐需要执行的测试用例
**以便** 快速确定测试范围，提高测试效率

### 验收标准
- [ ] AC1: 能够在推荐页面输入版本号、修改内容、修改模块、风险等级
- [ ] AC2: 能够点击"获取推荐"按钮调用 Azure OpenAI API
- [ ] AC3: AI 返回推荐的测试用例列表，包括推荐理由
- [ ] AC4: 推荐结果包括：冒烟测试、语音专项回归、系统级回归等
- [ ] AC5: 能够查看每个推荐用例的详细描述和执行步骤
- [ ] AC6: 能够保存推荐结果到本地数据库
- [ ] AC7: 能够查看历史推荐记录
- [ ] AC8: 如果 API 调用失败，显示友好的错误提示

### 业务规则
- 推荐逻辑基于三层策略：版本分析 + 风险等级 + 历史问题
- 高风险版本推荐全链路回归
- 中风险版本推荐冒烟 + 语音专项回归
- 低风险版本推荐冒烟 + 定向测试

### 技术考虑
- 集成 Azure OpenAI API (eastus 区域)
- 实现请求缓存（相同输入不重复调用）
- 实现错误重试机制
- 显示 API 调用状态和进度

- [ ] AC6: 能够编辑问题信息和状态（开放/进行中/已解决）

- [ ] AC8: 能够删除问题记录

### 业务规则
- 问题状态只能是：开放/进行中/已解决
- 问题分类由 AI 自动生成
- 支持手动修改分类
- 记录问题的创建时间和更新时间

### 技术考虑
