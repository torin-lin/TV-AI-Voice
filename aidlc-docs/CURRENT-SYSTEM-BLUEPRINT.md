# 当前系统蓝图与后续排期

最后更新：2026-04-08

## 一、当前项目定位

这个系统已经不再只是“测试记录工具”，当前更准确的定位是：

`AI Voice 版本提测与回归协作平台`

它围绕版本主线，承载了三类核心角色：

- `RD`：提交变更、完成冒烟、发起提测
- `QA`：围绕 RD 版本做固件维度回归和问题管理
- `项目负责人 / 管理者`：在版本工作台和仪表板查看风险、阻塞和准出结论

## 二、当前系统主流程

```text
RD 录入 Release Note
  -> 补充风险、模块、功能、修复 PR、APK
  -> 完成 RD 冒烟
  -> QA 选择“关联 RD 版本”创建测试记录
  -> 在不同固件上执行语音功能回归 / 系统集成回归
  -> 产生版本问题 / 追踪问题
  -> 版本工作台聚合分析
  -> 填写结论卡与版本状态
  -> 可发布 / 已发布
```

## 三、核心模块现状

### 1. Release Note (RD)

职责：
- 研发变更输入中心
- 提测前自检入口

已具备：
- 父子版本结构
- 回归风险、受影响模块、受影响功能
- 修复 PR、APK 上传
- `RD 冒烟测试`
- QA 记录数 / 固件覆盖数反查

当前问题：
- 主列表已优化，但展开区仍可以继续做交互增强
- 与 QA 记录的跳转还可以更直接

### 2. QA 版本记录

职责：
- 对 RD 版本执行固件维度测试

已具备：
- 只能关联 `RD 冒烟通过` 的版本
- 关联 RD 版本后自动回填基础信息
- 一个 RD 版本支持多个固件测试
- 版本状态、结论卡、导出

当前问题：
- 部分字段仍有进一步收敛空间
- 与版本工作台之间还可以更强绑定

### 3. 版本工作台

职责：
- 版本主线聚合页

已具备：
- 聚合 Release Note、QA 记录、版本问题、追踪问题、推荐结果
- RD 提测信息汇总
- 版本状态机
- 结论卡保存
- 风险提醒与推荐状态

当前问题：
- 还缺真正的历史视角
- 缺少时间轴和检查清单

### 4. 问题追踪

职责：
- 客户问题和 QA 问题统一追踪

已具备：
- 状态管理
- 分类
- PR 号与固件信息链路
- 客户问题 / QA 问题分区

当前问题：
- 缺少更强的 SLA 和责任视角
- 与版本工作台的联动还可以更直接

### 5. 仪表板

职责：
- 管理视图和风险概览

已具备：
- 风险等级分布
- 问题分类 / 状态分布
- 版本状态分布
- 最近 QA / RD / 问题概览

当前问题：
- 还偏“统计展示”
- 离“管理决策面板”还差一层

## 四、当前架构梳理

### 前端
- `React + TypeScript + Vite`
- `Redux Toolkit` 管理跨页面状态
- `React Router` 管理页面流转
- `Tailwind CSS` 管理样式

### 服务端
- `Express`
- `better-sqlite3`
- 路由负责 CRUD、校验和业务规则

### 公共底座
- `src/config/dictionaries.ts`：字典中心
- `src/i18n/*`：中英文切换
- `src/components/common/ToastProvider.tsx`：统一提示

## 五、当前数据模型关系

### ReleaseNote
- RD 变更对象
- 是 QA 创建测试的前置入口

### VersionRecord
- QA 测试对象
- 通过 `releaseNoteId` 关联 `ReleaseNote`

### VersionIssue
- QA 测试中的版本问题
- 绑定单条 `VersionRecord`

### CustomerProblem
- 客户问题 / QA 问题追踪对象

### KBRecommendation
- 版本级测试建议

## 六、已落地的流程规则

### RD -> QA 准入规则
- 只有 `RD 冒烟通过` 的 Release Note 才能被 QA 选中

### QA 版本规则
- `关联 RD 版本` 为唯一主入口
- 同一个 RD 版本允许多个固件测试记录

### 版本状态规则
- `待测试 -> 测试中 / 阻塞`
- `测试中 -> 阻塞 / 待结论`
- `阻塞 -> 测试中 / 待结论`
- `待结论 -> 阻塞 / 可发布`
- `可发布 -> 已发布 / 阻塞`

### 准出规则
- `可发布 / 已发布` 必须填写：
  - 结论摘要
  - 结论负责人

## 七、后续优化蓝图

### P0：补齐版本闭环

1. 版本状态变更时间轴
- 展示版本状态、结论卡、RD 冒烟、关键回归结果的变化历史

2. 发布前检查清单
- 统一展示准出前必须满足的条件

3. RD / QA / 问题三方跳转闭环
- 从 Release Note 能直接钻到 QA 记录和工作台
- 从工作台能快速跳到问题追踪

### P1：补强管理视角

1. 仪表板升级为管理面板
- 超时问题
- 阻塞版本
- 高风险版本
- 未结论版本

2. 问题 SLA / 责任机制
- 责任人
- 预计完成时间
- 超时标记

3. 版本结论历史
- 谁在什么时候给出过什么结论

### P2：升级为项目协同系统

1. 需求 / 任务池
2. 测试计划与执行
3. 发布审批流

## 八、建议的近期执行顺序

建议按下面顺序继续推进：

1. `版本状态变更时间轴`
2. `发布前检查清单`
3. `Release Note / QA / 问题跳转闭环`
4. `仪表板管理化`
5. `问题 SLA`

## 九、当前最值得继续做的下一步

如果继续沿当前主线推进，最自然的下一个功能是：

`版本状态变更时间轴`

原因：
- 它能把“版本是怎么走到当前状态的”讲清楚
- 也能和工作台、结论卡、提测信息自然衔接
- 做完之后，版本工作台就更像真正的版本主页面了
